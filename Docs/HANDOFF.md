# DEAL-ME-IN 작업 인계

마지막 갱신: 2026-09-21 (한국 시간)

## 이 문서의 목적

컴퓨터나 Codex 대화가 바뀌어도 프로젝트 맥락을 이어가기 위한 작업 요약이다. 대화 원문 백업이나 Codex 앱 대화 동기화 설정은 아니다. 저장소에 올라온 내용만 다른 환경에서 확인할 수 있다.

## 현재 요청과 합의

- 최신 작업은 `codex/tetromino-upgrades`: 사용자가 회전 없는 도장형 강화와 열쇠 블록 방식을 확정하여 구현했다. `Docs/TetrominoUpgrades.md`를 먼저 읽는다.
- 구현 완료: 고정 방향 후보 3개, 배치/점수 미리보기, 확정 후 4칸 성장, 열쇠 1칸만 해금, 유효한 열쇠 후보 보장, 반복 정비 성장 및 새 런 초기화, 블록→카드 정비 흐름. 기존 이펙트 변경을 포함한 브랜치다.
- 검증: 독립 .NET에서 블록 949개·딜러 138개·핵심 92개 통과, 런타임/Play 검사 코드 C# 컴파일 성공. 실제 Unity Play 검증은 라이선스 IPC 문제로 아직 미완료다. 다음은 실제 UI와 네 칸 강화 밸런스 확인이다.

- 사용자는 다른 컴퓨터에서 진행하던 DEAL-ME-IN 작업을 노트북에서 이어가려 한다.
- 사용자는 환경을 다시 바꿔도 작업 맥락이 남기를 원한다. 프로젝트의 결정, 진행 상황, 다음 단계를 이 문서에 유지한다.
- 현재 대화에서는 GitHub 저장소와 README, 최근 커밋을 확인했다. 이전 컴퓨터의 대화 원문은 읽지 못했으며, 푸시되지 않은 변경사항은 확인하지 못했다.
- 최신 요청: 득점과 버스트를 훨씬 강렬하게 느낄 수 있도록 화면·사운드 이펙트를 강화한다.

## 진행 중: 득점 / 버스트 연출 강화

- 작업 브랜치: `codex/score-bust-spectacle`. 이 변경을 이어갈 때 main만 읽지 말고 해당 브랜치 및 연결된 PR을 확인한다.
- 구현: 단계별 배수 팝업, 목표 대비 득점에 따른 NICE / BIG / MEGA / JACKPOT, 큰 점수 슬램, 최대 72개 파편, 충격 글로우, 테이블 진동, 상승 아르페지오.
- 버스트: 짧은 정적 → BUST 스탬프 → 카드 파편 낙하 → 실제 차감 점수와 끊긴 연속 성공 표시 → 회복 문구. 하강 불협화음과 저음 충격을 사용한다.
- 취소 시 사운드 정지, 숨긴 합계와 테이블 위치 및 입력 복구. 게임 RNG·점수·지급 규칙은 변경하지 않았다.
- 검증 완료: Unity 6000.3.24f1의 C# 컴파일러 및 Unity 엔진/템플릿 UI·InputSystem DLL로 런타임 전체와 PresentationPlayChecks 컴파일 성공. 기존 labReport 미할당 경고만 존재한다.
- 독립 .NET 하네스에서 기존 검사 본문과 실제 TableBalance.json을 사용하여 딜러 138개, 핵심 92개 통과. Unity 리소스 로딩을 JSON 역직렬화로 대체한 규칙 검사이며 Play 모드 검증이 아니다.
- 미완료: Unity 배치 실행은 라이선스 IPC 연결 거부 및 초기화 대기에서 멈춤. 실제 렌더링, 사운드 체감, 새 Play 모드 회귀 검사는 아직 실행하지 못했다. 통과한 것으로 보고하지 않는다.
- 다음 단계: 이 브랜치를 Unity에서 열어 `PresentationPlayChecks.Start()`를 실행하고 점수/버스트/건너뛰기/새 런을 확인한다. 자동 실행 진입점은 `PresentationChecks.RunPlay`이며 `-quit` 없이 사용한다. `DEALMEIN_CAPTURE_DIR`를 지정하면 검사 중 스크린샷을 저장한다.
- 사용자에게 보여줄 다음 기능을 임의로 추가하기보다 이번 효과의 시각·청각 검증 및 피드백 조정을 우선한다.

## 다음 작업

1. 현재 컴퓨터의 프로젝트 체크아웃 및 Unity 설치 상태를 확인한다. 없으면 저장소를 clone하고 README의 실행 절차를 따른다.
2. 기존 체크아웃은 `git status`로 미커밋 변경을 먼저 확인한다. 변경을 보존하고 원격 변경을 반영하며 강제 덮어쓰기하지 않는다.
3. Unity에서 NumberTable 씬 실행을 확인한다. Unity MCP는 컴퓨터마다 별도 연결이 필요하며 아직 이 노트북에서 연결 확인하지 않았다.
4. 사용자가 이어가려는 구체적인 기능/수정 내용을 확인하고 관련 코드와 문서를 읽는다.
5. 의미 있는 작업이 끝나면 이 문서의 현재 상태, 결정 이유, 검증 결과, 남은 일을 갱신한다.

## 기기 전환 절차

- 시작: 최신 저장소를 가져온 뒤 `AGENTS.md`, 이 문서, `README.md`를 읽는다.
- 종료: 작업 요약을 갱신하고, 허용된 범위의 변경을 commit/push하여 GitHub 반영 여부를 확인한다. 로컬 저장만 했으면 기기 간 공유가 완료된 것으로 말하지 않는다.
- 코드 푸시 권한/범위가 불분명하면 최소한 인계 문서의 저장 상태와 미공유 변경을 사용자에게 명확히 알린다.
- 다음 환경에서 쓸 요청: "yujin102911/DEAL-ME-IN의 AGENTS.md와 Docs/HANDOFF.md를 읽고 이어서 작업해줘."
- 이 공개 저장소에는 대화 원문, 개인정보, API 키, 인증 토큰, 컴퓨터별 비밀 설정을 저장하지 않는다.
